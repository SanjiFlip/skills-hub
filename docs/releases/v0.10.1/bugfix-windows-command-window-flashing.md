# Windows 命令窗口闪烁修复

## 问题

[Issue #150](https://github.com/qufei1993/skills-hub/issues/150) 报告在 Windows 11 上运行 Skills Hub v0.10.0 时，会频繁闪现多个命令窗口。

应用原本每 5 秒刷新一次自动更新状态。这个刷新调用了完整配置接口，而完整接口会同步查询操作系统的计划任务状态。在 Windows 上，该查询通过 `schtasks /Query` 子进程执行；图形界面应用如果没有为子进程显式禁用控制台窗口，Windows 会短暂创建可见命令窗口。启动时的重复配置读取和手动更新期间更密集的状态轮询会进一步放大这一现象。系统 Git 子进程也存在相同的窗口创建风险。

macOS 和 Linux 不会出现同样的 Windows 命令窗口，但旧实现仍会在每次轮询时分别运行 `launchctl` 或 `systemctl`，造成不必要的系统进程开销。因此，高频系统任务查询是跨平台设计问题，可见闪窗是 Windows 特有表现。

## 修复

- 新增只读取 SQLite 运行状态和逐项进度的轻量接口，5 秒后台刷新及手动更新等待均不再查询操作系统计划任务。
- 应用启动时只读取一次完整自动更新配置，移除重复的系统任务状态查询。
- 所有计划任务命令和系统 Git 命令统一通过后台进程入口启动；Windows 使用 `CREATE_NO_WINDOW`，macOS 与 Linux 保持普通子进程行为。
- 新增前端集成回归测试，锁定“完整配置仅在启动时读取一次、定时刷新仅调用轻量接口”的行为。
- 新增独立的 Windows CI 运行探针，直接启动使用生产进程封装的子进程，并通过 Win32 `GetConsoleWindow` 验证其没有控制台窗口。该探针不依赖 Tauri 测试运行时，可规避既有 Windows 测试程序启动环境问题。

## 最终行为

自动更新仍会每 5 秒刷新运行进度，以便在任意页面及时展示后台更新结果；该轮询现在只访问本地数据库，不会启动 `schtasks`、`launchctl` 或 `systemctl`。操作系统计划任务只在读取完整设置、保存计划、立即触发等确实需要它的操作中查询或修改，且 Windows 子进程不会显示命令窗口。
