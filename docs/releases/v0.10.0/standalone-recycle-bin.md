# 独立回收站设计

Skills Hub 将删除恢复功能从“设备同步”中独立出来。删除的 Skill 会进入本机回收站，并保留 30 天。

## 功能行为

- 用户手动删除和设备同步触发的删除，都会生成相同格式的完整恢复快照。
- 快照保存 Skill 文件、描述、标签、启用状态、来源信息和工具同步关系。
- 恢复时重新创建 Skill 记录并还原文件。原工具目录仍可使用时，自动重新建立同步关系；无法恢复的工具关系会保留为异常状态，供用户稍后处理。
- 永久删除会立即移除备份文件和对应的恢复记录，之后无法找回。
- 用户可以一键清空回收站。该操作始终处理全部项目，不受当前搜索条件影响。
- 回收站数据只保存在当前设备，不写入 Git 同步仓库，也不会传到其他设备。

## 30 天自动清理机制

每条回收站记录包含删除时间和过期时间，过期时间固定为“删除时间加 30 天”。

应用启动后会立即检查一次回收站，删除已经过期的记录和备份文件。应用保持运行时，每隔 24 小时再次检查。应用没有运行时不会启动额外的系统定时任务；下次打开应用后会补做检查。

清理过程中，只有备份文件成功删除后才会移除数据库记录。如果文件删除失败，该记录会继续保留，等待下一次自动清理，避免出现记录消失但文件残留的情况。

## 恢复安全设计

- 恢复前先确认同一 Skill 尚未重新安装，避免覆盖现有数据。
- 原托管目录被其他内容占用时停止恢复，不覆盖已有文件。
- Skill 文件成功复制但数据库恢复失败时，会撤销刚创建的文件，回收站记录继续保留，用户可以再次尝试。
- 工具同步关系先按“待恢复”状态写入数据库，再逐项重建。某个工具恢复失败不会影响 Skill 本身和其他工具的恢复。
- 删除、恢复、永久删除和自动清理使用同一把本机操作锁，避免多个操作同时修改同一条回收站记录。

## 数据与兼容性

回收站复用现有恢复记录表，并通过新增字段保存删除来源和完整快照。数据库使用独立的功能版本标记，不提高共享数据库版本，因此上一个稳定版本仍可安全打开数据库。

旧版设备同步产生的恢复记录仍可读取和恢复；旧记录没有保存的信息无法补造，但不会阻止用户取回已有文件。

## 验证范围

回归测试覆盖以下场景：

- 删除与恢复后，文件、描述、标签、来源、启用状态和工具同步关系保持完整。
- 只清理超过 30 天的项目，未过期项目继续保留。
- 数据库恢复失败时撤销新文件，并保留可重试的回收站记录。
- 旧数据库可以原地增加回收站字段，共享数据库版本保持不变。
- 前端可以查看保存的信息，并且永久删除必须经过二次确认。
- 一键清空会删除全部备份文件和恢复记录，并要求输入指定确认文字后才能执行。

## 页面说明与详情交互

顶部的“回收站说明”可点击展开，解释 30 天保留期、启动及运行期间每隔 24 小时的清理机制、恢复内容和本机存储范围。点击外部或按 Esc 收起说明。

关闭右侧详情后，列表自动占满宽度。搜索时保持收起，点击某条记录后再显示详情。

## 页面布局

页头将标题、项目数量、说明入口、搜索和“清空回收站”操作合并，减少顶部空白。清空操作位于搜索框旁，并在回收站为空、加载中或正在清空时禁用。列表按实际宽度收起删除来源、删除时间等次要列，优先显示 Skill 名称和剩余时间。详情区支持长名称和路径换行，恢复摘要不再重复套用卡片边框；仅剩余 7 天以内的项目使用警示色。

回收站直接使用应用主内容区的统一外边距，不再叠加页面内边距；普通窗口、窄窗口和侧栏收起时均与其他页面对齐。

## 工具展示与恢复口径

回收站复用 Skill 卡片的筛选规则：只统计当前启用、已安装且在对应范围内同步成功的工具，并使用相同的工具显示名称。数量按工具去重，多个同步目录不会重复计数。已有回收站记录也适用此规则。

恢复时只重建展示工具对应的同步关系；其他历史关系仍保留在本机记录中，但设为停用，不重新创建工具目录。

## 与系统废纸篓的职责划分

删除整个 Skill（包括手动删除与设备同步删除）只进入 Skills Hub 本机回收站。处理顺序如下：

1. 读取文件、描述、标签、来源、启用状态和工具关系，复制文件到独立备份目录。
2. 在数据库事务中保存恢复快照并移除托管记录。保存失败时不清理原文件和工具目标。
3. 保存成功后直接清理托管副本及工具目录中的副本、软链接或 Windows 目录联接，不再送入系统废纸篓。链接只解除自身，本地原始源目录始终保留。
4. 清理失败时报告错误，已保存的回收站文件和恢复记录继续保留；这时部分旧文件可能仍在原位置。

永久删除和 30 天过期清理直接移除本机备份，不再转入系统废纸篓。已有系统废纸篓内容不迁移、不清空。

取消同步、停用、迁移目录、覆盖冲突等未建立完整 Skill 回收站快照的操作，继续沿用原有文件保护规则，不全局取消系统废纸篓功能。

上述顺序保证备份先于清理，但不表示文件系统和数据库具备跨进程崩溃的原子性：异常退出后可能留下额外备份或原位置残留，不应自动清理无法确认归属的文件。

## 删除确认界面

单个和批量 Skill 删除按钮统一使用“删除”，弹窗标题使用“删除 Skill”；顶部内容说明删除后移入 Skills Hub 本机回收站，并说明文件与本机配置保留 30 天、工具同步副本移除、本地原始源目录保留。此操作使用浅红按钮；回收站永久删除使用实心红色按钮并明确无法恢复。单个、批量、永久删除及标签删除复用统一确认弹窗，保持内容区和底部内边距、按钮排列、键盘焦点和加载期间禁止关闭的行为一致。自定义工具移除与缓存清理沿用该公共确认框。

清空回收站会在弹窗中显示即将永久删除的项目总数，并要求用户输入当前界面语言下的“清空回收站”确认文字。文字完全匹配前，最终的实心红色“永久清空”按钮保持禁用；搜索结果不会缩小清空范围。

打开确认弹窗时会冻结待删除记录的完整 ID 集合。后端取得回收站操作锁后再次比对当前集合；如果后台设备同步、恢复或其他操作使列表发生变化，本次清空会在删除任何内容前停止，刷新列表并要求用户重新确认，避免永久删除确认时尚未出现的新记录。

## 错误提示国际化

回收站加载、恢复、永久删除和清空失败由前端按应用语言显示中、英、韩提示。后端用稳定错误码区分位置占用、Skill 已存在、记录不存在、备份丢失及快照损坏；前端兼容旧版英文错误。未知错误显示当前操作的失败说明，不直接展示内部英文异常。恢复位置占用时明确提示检查现有文件且不会覆盖原内容。清空过程中若部分项目已经移除后遇到错误，页面会重新读取列表，准确显示仍可重试的剩余项目。

## 保存位置说明

回收站说明展开后从当前设备读取并展示两类文件备份路径：手动删除备份位于应用数据目录下的 `recycle-bin/`，设备同步删除备份位于 `device-sync/trash/`。数据库由应用内部管理，不在用户说明中展示。路径可选中复制，长路径自动换行。每条删除记录有独立备份子目录，目录在需要时创建。读取路径不会创建目录、执行同步或访问凭据。

## 侧边栏入口分组

工作区仅保留「我的 Skills」和「添加 Skills」。管理中心依次为「设备同步」「标签」「工具」「更新」「回收站」；设置继续固定在底部。设备同步和回收站保留独立页面，原有数量角标、选中状态与折叠提示保持一致。
