# 设备同步可靠性与安全修复

本文汇总 v0.10.0 多设备同步功能完成后的可靠性、安全性和交互修复。该功能回应了 [Issue #56](https://github.com/qufei1993/skills-hub/issues/56) 提出的跨设备 Skill 环境一致性需求；初始产品决策、仓库格式及模块设计见[多设备同步架构设计](device-sync-architecture.md)。

相关 PR：[#134](https://github.com/qufei1993/skills-hub/pull/134)、[#136](https://github.com/qufei1993/skills-hub/pull/136)、[#137](https://github.com/qufei1993/skills-hub/pull/137)、[#139](https://github.com/qufei1993/skills-hub/pull/139)、[#140](https://github.com/qufei1993/skills-hub/pull/140)。

## 首次同步与冲突处理

- 新设备不会再把远端已有、但本机尚未下载的 Skill 误判为本机删除。
- 处理单个冲突时，只保存该 Skill 对应的远端基线，不推进整个仓库的成功同步基线。
- 冲突选择会跨重启和重试保留，并在后续完整同步成功后失效。
- 采用远端或保留双方时，读取冲突记录中固定的 Git 提交，校验路径、文件哈希和清单，并保留可执行权限。
- 实际处理结果单独记录为冲突处理活动，不会误报为整个库同步成功。

任一未解决冲突都会阻止本轮发布和本机内容应用。远端拒绝非快进推送时，会重新拉取、比较并完整重试一次；再次失败时停止，不更新托管库或同步基线。

## 文本三方自动合并

设备同步继续以上次同步基准、本机导出快照和远端最新提交作为三方输入。不同文件或单边修改沿用原规则；同一 UTF-8 文本文件被双方修改时，通过内置 libgit2 文本驱动尝试合并不重叠的修改。

自动合并遵循以下边界：

- 三份输入均须为 UTF-8、不含 NUL，且每份不超过 1 MiB。
- 不执行外部 Git 命令、仓库脚本或自定义合并驱动，也不使用 `ours`、`theirs` 或 `union` 强制选边。
- 基准及远端文件必须来自确定的提交，并与清单 SHA256 一致；缺失、篡改、越界路径和符号链接均中止处理。
- Git 历史发生 LF/CRLF 归一化时，仅在恢复后哈希完全一致时接受；混合换行不自动合并。
- 双方新增同一路径、删除与修改并发、二进制、超限输入及元数据歧义继续交由用户处理。
- 合并结果会重新计算文件及 Skill 哈希，并重新执行完整私钥标记检查。

该能力只保证文本级合并，不保证自然语言、YAML 或嵌入代码在语义上正确。

## 每台设备独立的来源归属

- 本地 Skill 的来源路径、子路径和本机版本不会进入共享清单；旧清单和历史基线会先规范化再比较。
- 每台设备保留自己的本地目录或 Git 来源绑定。其他设备首次接收本地 Skill 时保持未绑定状态，不把托管副本错误标记为原始来源。
- 未绑定 Skill 可正常使用、分发到工具并参与设备同步，但不能执行来源更新，也不会进入自动来源更新候选。
- 本机来源归属标记随安装、删除、重装和身份合并维护；旧版导入的外来路径或自绑定路径会在后续同步中修复。
- 修复外来绑定时只清除对应的来源缺失异常，不影响其他来源或工具异常。

每个来源还保留“上次从该来源导入的内容”基准。来源未变化时，定时来源更新不会覆盖设备同步带来的较新内容；来源实际变化或用户明确执行更新时仍会应用。本机旧记录会在首次远端替换前建立保守基准。

同一批下载会预留全部托管路径。同名 Skill、短 ID 冲突、符号链接或已有非托管目录会使用递增的唯一目录，不覆盖现有内容。

## 本机文件保留

上传过滤与本机目录替换现在使用不同边界：

- `.env`、依赖和缓存等内容继续不上传，但从远端回写时保留本机已有文件。
- `dist`、`build` 目录中的正常 Skill 文档可以同步；旧仓库中过度宽泛的对应忽略规则会迁移。
- 本机符号链接只保留链接本身，不跟随读取，也不上传链接目标。
- Python 字节码缓存只在工具复制冲突比较中忽略；文档、权限、链接和回滚指纹继续严格保护。
- 旧版本已经丢失的文件不会自动恢复，需要从可信上游或完整副本取回。

## 中央库与工具分发边界

设备同步的合并输入只包含中央库与 Git 快照，不包含工具目录中的复制副本。中央库文件和元数据更新完成后，再刷新已登记的复制型工具目标；符号链接目标继续直接指向中央库。

- 工具副本异常写入工具关系状态，不会将已经成功的云端同步标记为失败。
- 同一 Skill 的多个工具关系共用一个物理目录时，只替换一次文件，并在同一事务中更新所有复制记录及基线。
- 不同 Skill 占用同一路径、真实副本编辑或替换期间的并发写入都会阻止覆盖。
- 复制目标只有匹配上次已知副本或当前中央内容时才允许更新；无法确认的差异不会登记为可信基线。
- Skill、标签、工具状态和副本基线使用同一数据库事务。数据库失败会回滚已经激活的目录替换，但不承诺断电级跨文件系统事务。

远端删除冲突选择采用远端时，本机 Skill 会进入 Skills Hub 回收站；恢复和“保留双方”不会套用上传过滤。完整恢复规则见[独立回收站设计](standalone-recycle-bin.md)。

## 仓库可见性与凭据访问

仓库选择器保存平台返回的公开、私有或内部可见性。手动地址和旧配置无法确认可见性时，后台检查及自动同步暂停，用户需要通过仓库刷新和选择流程重新确认。

- 公开 HTTPS 仓库的只读检查不读取系统凭据，也不会在匿名失败后自动读取凭据重试。
- 私有或内部 HTTPS 仓库读取需要凭据；上传使用独立的写入鉴权。
- 公开仓库上传前必须确认 Skill 内容和设备信息将公开。
- SSH 使用系统 SSH Agent，不读取 OAuth Token。
- 修改仓库地址会清除旧可见性和公开上传确认。

可见性只保存在本机，不替代远端权限校验。仓库权限发生变化后，需要重新选择或刷新设置。

## 异常状态与失败原因

- 来源更新、设备同步和工具分发使用独立状态；设备同步成功不会清除来源更新失败。只有来源更新成功或确认来源无变化时才清除来源异常，旧版来源缺失记录会保守提示重新检查。
- 后台更新进度变化时会刷新 My Skills 和已打开的详情，无需先进入更新页。
- 待处理工具分发显示为部分完成，并区分历史失败和当前恢复状态。
- 页面顶部持续展示最近一次同步失败的原因；历史记录可展开查看恢复建议，不再显示无意义的全零统计。
- 手动同步失败后立即刷新状态，不重新加载仓库选择器或清空未保存设置。

后端只保存白名单诊断码，不保存原始错误链、URL、Token、响应正文或文件内容。旧历史在读取时转换为安全诊断码，不重写旧数据库；未知错误使用通用提示，不回显任意异常文本。

## 同步历史

- 已有 Skill 的单侧变化计为更新，只有新 ID 计为新增；统计在执行合并计划前完成。
- 新记录保存 Skill 名称、变化类型和方向；旧记录没有足够证据时标记为“旧版统计 · 未校正”。
- 内部缓存和仅设备登记变化不会生成内容同步历史。
- 冲突计划明确显示尚未应用；采用远端和保留双方的结果单独记录。
- 仅保留最近 100 条有效记录，包括内容变化、冲突、失败和冲突处理活动。
- 成功但无内容变化的运行只更新最近检查状态，不占用历史名额。
- 中断遗留的“运行中”记录不展示，并在下一次同步开始时清理。
- 裁剪历史时，在同一事务中删除对应的逐项明细；旧开发版本的超量记录也会在下一次完成运行后收敛。
- 页面首次加载 50 条，再按需加载剩余 50 条，到达上限后隐藏继续加载入口。

## 设备记录与同步页面

同步页面顶部使用三行紧凑布局，分别展示最近结果与操作、本机和仓库关系、自动同步设置。设备活动页展示设备名称和最近同步时间，不再推断在线状态或版本是否落后；接入其他设备的步骤与同步原理说明分开展示。

仓库根目录的 `devices.json` 按设备 ID 保存共享名称和最近同步时间。时间表示最近一次发布同步，不是在线心跳。同步会保留其他设备记录和兼容的未知 JSON 字段，只更新当前设备；即使 Skill 内容未变化，更新时间也可能产生纯设备元数据提交，但不会生成内容同步历史。本机修改设备名称后，在下一次同步时发布。旧版本机备注可迁移为当前设备名称，但不能继续覆盖其他设备。

过期推送会重新拉取、合并并重试一次。损坏、过大、版本不支持或符号链接形式的设备记录会中止同步，不覆盖远端内容。旧仓库可从提交尾部记录迁移，并继续写入兼容标记。设备列表读取本机缓存，不打开 Git 或读取凭据；完成“检查变化”后会立即刷新。

复制设备授权码成功后显示短暂成功反馈；失败时显示安全提示并允许重试，不展示异常原文。

GitHub 浏览器授权复用设置页中的 GitHub 网络代理。设备码申请、Token 轮询及授权后的账号校验使用同一代理配置，避免系统代理未被桌面进程继承时直连 GitHub 超时；GitLab 与 Gitee OAuth 不读取该 GitHub 专用设置。

## 数据兼容性

这些修复使用功能级设置保存逐项历史、来源归属和副本基线，不提高共享数据库 `PRAGMA user_version`。上一稳定版本可忽略新增数据。涉及路径隔离的新同步语义需要参与同步的设备都升级到 v0.10.0。

## 验证范围

回归测试使用临时数据库和真实本地裸 Git 仓库覆盖：

- 首次同步、三种冲突选择、重启、重试及过期推送。
- 同文件非重叠合并、重叠修改、Unicode、CRLF、空文件、二进制、大小边界和快照篡改。
- 私钥标记、凭据主机边界、仓库可见性和公开上传确认。
- 本机来源隔离、来源更新优先级、同名下载和旧数据修复。
- 本机排除文件、正式构建目录文档、符号链接、工具副本编辑及并发回滚保护。
- 同步计数、逐项明细、失败诊断、历史裁剪和设备记录兼容。

最终项目检查结果见本次发布分支的验证记录；本文不保留各中间 PR 当时的累计测试数量。
