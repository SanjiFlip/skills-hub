# Gitee 手动 Token 同步修复

## 问题

当前构建未配置 Gitee 浏览器授权时，用户只能通过 Token 或 SSH 连接。手动填写 HTTPS 仓库地址和 Token 后，界面要求先由平台确认仓库可见性，但仓库加载与选择区域仅对浏览器授权用户显示，导致首次同步无法继续。

## 修复

- 手动输入 Token 后显示现有仓库加载与选择区域。
- 用户主动点击加载仓库时，将当前 Token 一次性传给 Gitee API，用于读取仓库列表和识别可见性。
- 仓库列表请求使用 Gitee 当前授权用户接口支持的 `visibility=all` 筛选，不再发送会被该接口拒绝的 `type=all` 参数。
- 选择私有仓库后沿用平台返回的可见性状态，再执行首次同步流程。

## 安全边界

- 输入 Token 不会自动触发网络请求；只有用户主动加载仓库时才访问平台。
- Token 不进入仓库地址、日志、数据库或同步内容。
- 最终保存连接时，Token 仍只写入操作系统安全凭据存储。
- 仓库可见性继续以平台响应为准，不提供可伪造的手动选项。
