# Skills Hub v0.10.3

v0.10.3 修复数据库被清空或丢失后无法从中央技能库恢复的问题：仍存在于 `~/.skillshub` 中的技能现在可以重新导入。

## 修复内容

- 中央技能库中已存在、但库中没有记录的技能，会重新出现在「发现可导入的技能」列表中。
- 当中央库中已有内容与所选来源一致时，**就地采纳**该目录：不复制、不产生重复目录，也不报错。
- 中央技能库本身作为发现来源列出，可像其他来源一样在「技能发现」中关闭。
- 内容不一致时仍然拒绝，避免误采纳中央库副本而丢弃用户实际选择的内容。
- 中央库目录已缺失的技能不再显示为正常，而是明确报告为异常并给出原因。
- 采纳同名目录时会**修复**已存在的空壳记录（保留其标签、启用状态与同步目标），不再产生重复技能。

## 背景

工具目录（`.codex/skills`、`.claude/skills` 等）中的技能目录都是指向中央库的 junction。技能发现机制刻意排除中央库路径以及链接指向中央库的条目，以避免重复导入——这在正常运行时是正确的，但也意味着数据库一旦被清空或丢失，工具扫描将找不到任何候选项，而中央库自身又从不作为扫描来源。

结果是数据仍在磁盘上完好保留，应用却完全看不到它；尝试用「添加技能 → 本地文件夹」指向 `~/.skillshub/<名称>` 也只会得到 `skill already exists in central repo`，换个名字则会把内容再复制一份。

## 验证

- Rust 单元测试覆盖：就地采纳（不复制、`source_ref` 为空、描述与哈希正确写入）、中央库扫描跳过已登记项与无 `SKILL.md` 的目录、内容不一致时仍然拒绝、发现来源可关闭。
- 完整门禁：`npm run version:check`、`npm run lint`、前端测试、`npm run build`、`cargo fmt --all -- --check`、`cargo clippy --all-targets --all-features -- -D warnings`。
